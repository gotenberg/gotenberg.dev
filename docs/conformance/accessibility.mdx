title: Make accessible PDFs
---

Produce PDFs that screen readers can follow, and PDF/UA-conformant ones.

## Tag, then make PDF/UA

A tagged PDF carries its structure: headings, paragraphs, lists, tables, figures. Chromium tags the PDF from your HTML with `nativeTaggedPdf`, and the `remediate` stage takes it to PDF/UA:

<Request
  route="/forms/chromium/convert/html"
  files={["index.html", "style.css"]}
  fields={{ nativeTaggedPdf: true }}
  stages={[{ op: "remediate", profile: "PDF/UA-1", language: "en-US" }]}
  output="invoice.pdf"
  response={`HTTP/1.1 200 OK
Content-Type: application/pdf
Gotenberg-Remediation-Residual: 0
Gotenberg-Remediation-Rolled-Back: 0`}
/>

Write semantic HTML, with headings, lists, tables and `alt` text on images, and the tags follow it. `language` sets the language screen readers pick their voice from.

## Check it

<Request
  route="/forms/pdf/validate"
  files={["report.pdf"]}
  fields={{ profile: "PDF/UA-1" }}
/>

## Where to go from here

- **Office documents:** LibreOffice tags a document with [`nativeTaggedPdf`](/docs/libreoffice/convert#nativeTaggedPdf) too.
- **A PDF you already have:** [`autotag`](/docs/pdf/autotag) infers its structure, and [`remediate`](/docs/pdf/remediate#make-it-pdfua) makes it PDF/UA-1 or PDF/UA-2.
- **Archival too:** one `remediate` stage takes a PDF/UA profile and a PDF/A one together, such as `["PDF/A-2b", "PDF/UA-1"]`: see [`remediate`](/docs/pdf/remediate#make-it-pdfa-and-pdfua). `PDF/A-2a` alone archives a tagged PDF, but doesn't make it PDF/UA.

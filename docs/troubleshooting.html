Version: 9.x

Troubleshooting

Find your symptom, then the fix. Every answer that isn't a PDF says what failed: start with its message, and its Gotenberg-Trace in Gotenberg's logs.

Answers​

400 after upgrading from 8.x​

Gotenberg 9 answers 400 for a field it moved, renamed or removed, and the message says where it went. Upgrade from 8.x lists every change.

400 Bad Request​

The message names the field and what it wants, such as form field 'paperSize' is invalid (got 'A9', want A3, A4, …). Errors shows the message styles.

403 Forbidden​

An outbound filter refused a URL the request names: the page Chromium loads, a downloadFrom file, a webhook or a timestamp authority. The message stays generic, and Gotenberg's logs say which rule refused it, as rule: deny-list, allow-list, private-ip, public-ip, unresolvable-host, invalid-url or pattern-error, or file-prefix for a page reading a file outside its own directory. See Secure Gotenberg.

409 Conflict​

The page Chromium loaded answered a 4xx or 5xx status, or failed another check you asked for. The message quotes the status or the console. See Fail on errors.

413, or a cut-off upload​

The request is larger than --api-body-limit. On Cloud Run, HTTP/1 requests stop at 32MB: use HTTP/2. On AWS Lambda, answers stop at 6MB: deliver with a webhook.

429 Too Many Requests​

The engine's queue is full: retry shortly, or run more containers. See Run in production.

503 Service Unavailable​

The request ran past --api-timeout, or Chromium crashed. A wait that never ends names itself. Look for a page that never gets ready, a document too heavy for the container's memory, or more requests than the containers serve.

Chromium​

The PDF misses what JavaScript draws​

Chromium prints as soon as the page loads. Wait for your page: see Wait for the page.

Backgrounds are missing​

Chromium prints the backgrounds of elements, but leaves the page's own background, the one set on html and body, out by default, as a browser's print dialog does. Set printBackground: true.

Images, styles or fonts don't load​

  • Link the files you upload by their names alone: src="logo.png", not src="img/logo.png". Gotenberg drops the folders.
  • localhost is the container itself, not your machine. On Docker Desktop, reach your machine at host.docker.internal.
  • The outbound filters drop a resource they block from the page, without failing the request. Gotenberg logs each one, with the rule that refused it:
{
  "level": "warn",
  "msg": "outbound request blocked by the Chromium filters",
  "correlation_id": "req-42",
  "url": "https://gotenberg.dev/img/logo.png",
  "rule": "deny-list"
}

The header or footer is tiny, or unstyled​

Header and footer templates need their own font size and <style> tag, and take images as data URIs only. See Add headers and footers.

landscape doesn't turn the page​

A CSS @page size keeps its own orientation. See Let the CSS decide.

Chromium failed to print the PDF​

The page is too large to print in one go: split its content across requests.

LibreOffice​

The layout shifts​

LibreOffice lays the document out with the fonts installed in the image. A font it lacks gets a substitute, and the lines break elsewhere. The image ships metric-compatible substitutes for the common ones: Liberation for Arial, Times New Roman and Courier New, Carlito for Calibri, Caladea for Cambria. For any other font, install it.

Linked images are missing​

LibreOffice drops the images and other content an uploaded document links to, since a document could make Gotenberg fetch any URL. Embed the images in the document. The style sheets an HTML file links are the exception: LibreOffice fetches them, under the outbound filters.

500 Internal Server Error​

LibreOffice failed to convert the document: the conversion ran out of memory or CPU, most often. The request is valid: retry it, give the container more resources, or split the document.

The document is password-protected​

Send its password in the password field. A missing or wrong one answers 400 and says which, except for a legacy .doc, .xls or .ppt sent without its password, which answers that LibreOffice couldn't read the document.

Fonts​

Install fonts​

Build your own image from Gotenberg's, with the fonts your documents use:

Dockerfile
FROM gotenberg/gotenberg:9

USER root

COPY fonts/*.ttf /usr/local/share/fonts/
RUN fc-cache -f

USER gotenberg

Chromium and LibreOffice both read the fonts installed in the image, and so do the stamp-text and flatten-form stages for text outside Western European, which the standard PDF fonts can't draw. Web fonts work without this on Chromium routes: upload the font files with the page, and declare them with @font-face.

Startup​

An engine doesn't start in time​

A slow machine or a cold start can outlast --chromium-start-timeout or --libreoffice-start-timeout, 20 seconds by default. Raise them.

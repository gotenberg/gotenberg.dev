Routes

Gotenberg serves every route below on port 3000, under --api-root-path: / by default. Each has its own page.

Chromium​

MethodRouteWhat it does
POST/forms/chromium/convert/urlPrints a web page to PDF.
POST/forms/chromium/convert/htmlPrints an HTML file, with the assets beside it, to PDF.
POST/forms/chromium/convert/markdownPrints Markdown files, laid out by an HTML template, to PDF.
POST/forms/chromium/screenshot/urlCaptures a web page as an image.
POST/forms/chromium/screenshot/htmlCaptures an HTML file as an image.
POST/forms/chromium/screenshot/markdownCaptures Markdown files, laid out by an HTML template, as an image.

LibreOffice​

MethodRouteWhat it does
POST/forms/libreoffice/convertConverts office documents, such as Word, Excel and PowerPoint files, to PDF.

PDF​

MethodRouteWhat it does
POST/forms/pdf/pipeRuns a list of stages on PDFs.
POST/forms/pdf/{op}Runs one stage, its options as form fields: /forms/pdf/merge, /forms/pdf/rotate, and so on.
POST/forms/pdf/infoReads the page count, the PDF version, and whether a PDF is encrypted, tagged, linearized, signed or holds form fields.
POST/forms/pdf/metadataReads the metadata: title, author, dates.
POST/forms/pdf/bookmarksReads the bookmarks.
POST/forms/pdf/attachmentsLists the embedded files.
POST/forms/pdf/formLists the form's fields: name, type, value, pages, and the values each takes.
POST/forms/pdf/validateChecks PDFs against PDF/A, PDF/UA or Factur-X, and lists the violations.

System​

MethodRouteWhat it does
GET/Answers a short note: Gotenberg has no UI.
GET, HEAD/healthReports whether Gotenberg and its engines are up.
GET/versionAnswers the version of Gotenberg.
GET/debugAnswers the modules, engine versions and flags, once --api-enable-debug-route is on.

Fields every route takes​

The POST routes take multipart/form-data. Besides their own fields, they all take:

FieldTakes
filesThe files to process, one upload each.
archivesZIP files, which Gotenberg unpacks as if you had uploaded their entries under files.
downloadFromURLs Gotenberg downloads first, as if you had uploaded the files.

The Chromium conversion routes, the LibreOffice route and /forms/pdf/pipe also take stages, which run on the PDFs they make or receive. The screenshot routes, the single-stage routes and the read routes answer 400 to it.

How requests work shows each one. The headers work on every route, except where they say otherwise.

What works where​

Which route takes which feature. A field name in code is a form field of the route. A stage name, such as stamp-text, goes in the route's stages field, or, on a single-stage route, is the route itself: /forms/pdf/stamp-text.

Two ways to the same result​

A field whose name starts with native asks the engine to do the work while it makes the PDF. A stage does it afterwards, the same way on every route. How Gotenberg works says which to pick.

An uploaded PDF on a conversion​

A conversion's stages see only the PDFs the conversion makes. To bring in a PDF you upload, name it in a stage that reads a file, such as insert or stamp-pdf. On the LibreOffice route, a PDF no stage names goes through LibreOffice like any document.

The system routes tell you about Gotenberg itself. They take no form.

<RouteTable group="system" />

With [authentication](/docs/configuration#api-enable-basic-auth) on, `/`, `/version` and `/debug` need credentials like the other routes. `/health` never does, so probes work without them.

Gotenberg doesn't log or trace these routes. Set [`--api-disable-health-check-route-telemetry`](/docs/configuration#api-disable-health-check-route-telemetry) and its siblings to `false` to change that.

## Health

`GET /health` reports whether Gotenberg and each of its engines are up:

<Request
  method="GET"
  route="/health"
  response={{
    status: "up",
    details: {
      chromium: { status: "up", timestamp: "2026-11-01T17:31:16.526522968Z" },
      libreoffice: {
        status: "up",
        timestamp: "2026-11-01T17:31:16.514805871Z",
      },
    },
  }}
/>

An engine that's down turns the status to `down`, with its `error`, and the answer to `503 Service Unavailable`. `HEAD /health` answers the same status, without the body:

<Request method="HEAD" route="/health" />

## Version

`GET /version` answers the version of Gotenberg, as plain text:

<Request method="GET" route="/version" response="9.0.0" />

The conversion and PDF routes send it too, in the `Gotenberg-Version` header.

## Debug

`GET /debug` answers what Gotenberg runs: its modules, the versions of Chromium and LibreOffice, and the value of every flag. It's off until you set [`--api-enable-debug-route`](/docs/configuration#api-enable-debug-route), and answers 404 before:

<Request
  method="GET"
  route="/debug"
  run={false}
  response={{
    version: "9.0.0",
    timezone: "UTC",
    architecture: "amd64",
    modules: [
      "api",
      "chromium",
      "libreoffice",
      "libreoffice-api",
      "pdf",
      "webhook",
    ],
    modules_additional_data: {
      chromium: {
        version: "Chromium 156.0.8078.73 built on Debian GNU/Linux 13 (trixie)",
      },
      "libreoffice-api": { version: "LibreOffice 26.8.1.1 680(Build:1)" },
    },
    flags: {
      "api-body-limit": "",
      "api-port": "3000",
      "api-timeout": "30s",
      "chromium-max-concurrency": "6",
    },
  }}
/>

The answer lists every flag; the example shows four. It reveals your configuration, so keep the route away from the public.

## Root

`GET /` answers a short HTML note that points here: Gotenberg has no UI.

<Request
  method="GET"
  route="/"
  response={`Hey, Gotenberg has no UI, it's an API. Head to the <a href="https://gotenberg.dev">documentation</a> to learn how to interact with it 🚀`}
/>

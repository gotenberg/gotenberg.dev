Stages process PDFs. List them in the `stages` form field, as JSON, and Gotenberg runs them in that order:

<Request
  route="/forms/pdf/pipe"
  files={["report.pdf"]}
  stages={[
    { op: "select", pages: "1-2" },
    { op: "stamp-text", text: "DRAFT", x: 72, y: 72, fontSize: 24 },
    { op: "optimize" },
  ]}
  output="report.pdf"
/>

## How stages work

- `stages` works on `/forms/pdf/pipe` and on every conversion route, where the stages run on the converted PDFs.
- Each stage works on what the previous one produced.
- A stage names the files it needs, such as an image to stamp or a certificate, by their uploaded names. Upload them under `files`: they don't count as PDFs to process.
- Each stage also has its own route, `/forms/pdf/<op>`, which takes the stage's options as form fields. Send a list or an object as JSON:

<Request
  route="/forms/pdf/rotate"
  files={["report.pdf"]}
  fields={{ angle: 90, pages: "1" }}
  output="report.pdf"
/>

## Order rules

Gotenberg checks the order of the stages before it runs any, and answers 400 with the rule a list breaks:

- `decrypt` comes first, and `render` last.
- A list has at most one `remediate` and one `encrypt`.
- After `remediate`, only `encrypt`, `optimize`, `sign`, `timestamp` and `render` may follow.
- After `encrypt`, only `optimize` and `render` may follow.
- After `sign` or `timestamp`, only `sign`, `timestamp` and `render` may follow.
- `encrypt` doesn't combine with `sign`, `timestamp`, or a PDF/A or Factur-X `remediate`.

## Page selections

An option of type `pages` takes a page (`3`), a range (`2-5`), a list of both (`1,3,5-7`), or `odd`, `even` or `last` on their own. Pages count from 1, and a page past the end answers 400.

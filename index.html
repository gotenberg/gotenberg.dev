01Conformance

Print anything. Prove it.

Validates any PDF against PDF/A, PDF/UA and Factur-X, clause by clause, and remediates what fails.

litho, a pure-Go PDF processor, takes over from QPDF, pdfcpu, pdftk and ExifTool, the tools behind Gotenberg 8's PDF engines. PDF/A and PDF/UA rules carry veraPDF's clause numbers.

Validate a PDF

  2. 6.2.4.3DeviceRGB shall only be used if a device independent DefaultRGB colour space has been set.test 2 · page 1: DeviceRGB used without DefaultRGB or RGB OutputIntent×9

02E-invoicing

Factur-X, ZUGFeRD. XRechnung too.

Send the invoice with its Cross-Industry Invoice XML: one remediate stage returns a PDF/A-3 hybrid invoice.

Embedded per Factur-X 1.07.2 and ZUGFeRD 2.3.2. Already hybrid? Leave out the XML: the same stage repairs the existing Factur-X. Validation adds Schematron warnings that do not fail conformance on their own.

03Deliver

Asynchronous, straight to S3.

One request in. The PDF lands in your bucket, an event tells you. Your server never touches the bytes.

Gotenberg fetches the source from a presigned GET URL and answers 204. It then uploads the PDF to a presigned PUT URL and sends an event to your events URL.

04Operate

25 stages write. 6 routes read.

Write stages change the PDF and send it back. Read routes leave it as it is and answer JSON. Three more stages, render, extract-attachments and extract-text, return images, files or text.

Gotenberg checks the order of the stages before it runs them: decrypt comes first, render or an extraction last, and nothing rewrites a signature.
